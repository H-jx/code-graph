# 四类提取器的调查规范

> 骨架文件。协议字段以 `crates/core/src/contract/` 导出并生成的 JSON Schema 为准。

## 通用要求

- 一个插件可以声明多类能力；插件 ID 与目录名不绑定框架。
- 输入来自 Core 导出的来源快照（文件路径 + 内容哈希 + 行范围），不自行扫描工作区。
- 输出统一为实体、关系、证据、依赖与覆盖缺口；项目可扩展类型，但不改公共字段。
- 每个结论都要能回到源码位置；动态值保留候选与缺失依据。

## routes

- 确认路由模式：hash / history / 文件路由 / 注册表；
- 提取 URL、别名、页面文件、标题与 i18n 来源；
- 记录参数与通配段；模板变量无法静态确定时标为候选。

## frontend

- 组件、按钮 / 事件与其处理方法；
- `fetch` / `axios` / GraphQL 请求点，以及请求 wrapper 的封装关系（baseURL、代理、拦截器）；
- 生成客户端（openapi / codegen）标注来源文件而非手写调用。

## api

- 服务边界与方法、路径（含归一化）；
- Handler / Resolver 及其调用的业务方法；
- 实例绑定与注册位置必须给出源码依据。

## database

- 数据源、ORM 模型与表列映射、复合键、关系基数；
- 读写与 join，区分声明（migration、模型定义）与推断（查询分析）；
- 已有 schema 导出文件可作为声明来源，但要记录版本。

## link

- 只在服务、方法、路径、数据源有明确绑定时建立跨层关系；
- 同名表跨数据源不得串联；绑定不明时输出候选，不建立边。
