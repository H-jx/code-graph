# 跨层关联（link）

> 骨架文件。运行时注入：extract 提交后的实体快照、服务与数据源边界、实际绑定位置。

## 目标

只在有明确绑定时建立跨层关系；每条关系有独立证据。

## 判定顺序

1. 服务边界一致：应用 / 服务 / 数据源作用域不同名不串联。
2. 路径与方法：按归一化后的方法 + 路径匹配，保留别名与模板变量候选。
3. 绑定位置：Handler、Resolver、实例绑定、ORM 模型映射必须能在源码中指出位置。
4. 数据侧：表列、复合键、关联条件来自声明或可核对的查询，不臆造基数。

## 输出要求

- `resolved`：绑定明确，附来源引用与行范围。
- `candidate`：同名或关键词重合，附缺失依据。
- `inferred`：由模型判断得出，必须标注并留待人工或脚本核对。
- 动态目标无法确定时写入缺口，不建立边。
